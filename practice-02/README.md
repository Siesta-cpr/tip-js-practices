## 4. Модель данных и функции

Поля задачи: `id` (положительное безопасное целое число, уникальное в списке), `title` (строка, после `trim()` длиной от 1 до 100 символов), `completed` (булево, `false` при создании), `priority` (одно из `"low" | "medium" | "high"`, по умолчанию `"medium"`).

Файлы:
- `src/data.js` — только данные (`demoTasks`, `variantNumber`, `variantTasks`), без логики и вывода.
- `src/task-service.js` — девять прикладных функций. Не содержит `console.log`, не импортирует `demoTasks` — каждая функция получает `tasks` аргументом.
- `src/main.js` — импортирует данные и функции, строит сценарий, выводит результат, обрабатывает отказы.
- `checks.js` — независимые проверки через `node:assert/strict`.

Формат результата операций изменения: при успехе `{ ok: true, tasks: <новый массив> }` (для `createTask` — `{ ok: true, task }`), при отказе `{ ok: false, error: "текст" }`.

- Почему `id` не равен индексу: индекс отражает текущее положение записи в массиве и меняется при удалении соседних элементов; `id` — постоянный идентификатор записи. Поиск по `id` выполняется через `find`, а не через обращение `tasks[id]`.
- Почему `getTaskStats` возвращает число, а не строку с процентом: округление и форматирование — задача представления (вывода), а не расчёта; `toFixed(1)` возвращает строку и применяется только в `main.js` непосредственно перед выводом, чтобы сам расчёт оставался точным и пригодным для дальнейших операций.
- Какие объекты копируются при изменении задачи: создаётся новый массив (через `map` или `filter`/`[...tasks, ...]`) и новый объект только для изменяемой записи (через spread объекта `{ ...task, ... }`); неизменённые записи массива переиспользуются как есть, без копирования.

## 9. Вывод

По сравнению с ПР1 данные теперь представлены не отдельными переменными, а объектами и массивом объектов; вся логика вынесена в отдельные функции и отдельный модуль (`task-service.js`), а не записана последовательно в одном файле. Функции изменения данных не меняют переданные объекты, а возвращают новый массив и — для изменённой записи — новый объект; это универсально проверяется через `{ ok, ... }`, а не через побочный эффект или исключение. Неизменность данных проверена как вручную (сравнение `demoTasks` до и после сценария в `main.js`), так и автоматически (`checks.js`, в том числе проверка № 33 с `Object.freeze`, которая гарантированно выбросит исключение при попытке мутации). Основная ошибка, которую пришлось исправить, — пропущенный `return` в стрелочной функции с телом в фигурных скобках (эксперимент 2): без него вычисление происходило, но результат терялся.
