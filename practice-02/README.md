## 4. Модель данных и функции

Поля задачи: `id` (положительное безопасное целое, уникальное), `title` (строка, после `trim()` длиной 1–100), `completed` (булево, `false` при создании), `priority` (`low | medium | high`, по умолчанию `medium`).

Файлы: `src/data.js` — данные; `src/task-service.js` — девять функций без DOM и вывода; `src/main.js` — сценарий и обработка отказов; `checks.js` — проверки через `node:assert/strict`.

- Почему `id` не равен индексу: индекс меняется при удалении соседних записей, `id` — постоянный идентификатор; поиск через `find`, а не `tasks[id]`.
- Почему `getTaskStats` возвращает число: округление — задача представления; `toFixed(1)` применяется только в `main.js` перед выводом.
- Какие объекты копируются: новый массив (`map`/`filter`/spread) и новый объект только для изменённой записи; неизменённые записи переиспользуются.

## 9. Вывод

Данные представлены объектами и массивом объектов вместо отдельных переменных; логика вынесена в отдельный модуль. Функции изменения не мутируют входные данные — возвращают новый массив и новый объект изменённой записи. Неизменность проверена вручную и автоматически (включая `Object.freeze` в проверке №33). Основная ошибка — пропущенный `return` в стрелочной функции с телом в фигурных скобках.
