## Организация кода

- `task-service.js` — операции над массивом задач без изменения входа (`addTask`, `setTaskCompleted`, `removeTask`, новая `updateTask`). DOM, форму и `localStorage` не использует. `updateTask` проверяет поля через `createTask`, но из его результата берёт только `title` и `priority`, поэтому `completed` сохраняется.
- `form-validation.js` — чистая функция `validateTaskDraft`: преобразует id через `Number` (пустую строку не превращает в 0), проверяет уникальность при создании, наличие задачи `editingId` при редактировании, `trim` и длину названия, приоритет. Возвращает все ошибки полей сразу и не обращается к DOM.
- `task-storage.js` — граница `localStorage`: проверка полной схемы (`isValidTaskList`), чтение с fallback (`loadTasks`), запись оболочки `{ version: 1, tasks }` (`saveTasks`), удаление одного ключа (`removeSavedTasks`). Все исключения хранилища перехватываются и превращаются в `{ ok: false, error }`.
- `task-view.js` — построение карточек, списка, сводки и пустого состояния; название выводится через `textContent`.
- `main.js` — текущее состояние (`currentTasks`, `currentFilter`, `editingId`), режим формы, обработчики событий и вызов сохранения после успешных операций. `renderApp` не обращается к хранилищу.

Функции хранения получают объект `storage` аргументом: внешняя зависимость видна в сигнатуре, а модуль можно проверить объектом-имитацией (так сделано в `checks/modules.checks.js`). Данные из JSON проверяются до использования, потому что успешный `JSON.parse` подтверждает только синтаксис: значение может иметь другую версию, неверные поля или повторяющиеся id.
